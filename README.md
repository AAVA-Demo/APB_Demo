# Credit Card Analysis Dashboard - Playwright Automation Framework\n\n## Overview\n\nThis is a production-ready Playwright JavaScript automation framework for testing the Credit Card Analysis Dashboard application. The framework follows the Page Object Model (POM) design pattern and implements enterprise-grade best practices.\n\n## Project Structure\n\n```\n.\n├── src/\n│   ├── automationScripts/\n│   │   ├── pages/\n│   │   │   ├── login.page.js\n│   │   │   ├── dashboard.page.js\n│   │   │   ├── cardManagement.page.js\n│   │   │   └── analytics.page.js\n│   │   ├── login.spec.js\n│   │   ├── dashboard.spec.js\n│   │   ├── cardManagement.spec.js\n│   │   ├── analytics.spec.js\n│   │   └── playwright.config.js\n│   └── utils/\n│       └── logger.js\n├── data/\n│   └── config.json\n├── logs/\n├── test-results/\n├── package.json\n└── README.md\n```\n\n## Features\n\n- **Page Object Model (POM)**: All locators and page interactions are encapsulated in Page Object classes\n- **Comprehensive Test Coverage**: 18 test cases covering all user stories\n- **Logging**: Winston-based logging utility for detailed test execution logs\n- **Configuration Management**: Environment-specific configurations in `data/config.json`\n- **Multi-Browser Support**: Tests run on Chromium, Firefox, and WebKit\n- **Responsive Testing**: Mobile, tablet, and desktop viewport testing\n- **Error Handling**: Robust error handling and retry mechanisms\n- **Reporting**: HTML, JSON, and JUnit reports\n\n## Test Coverage\n\n### Login Tests (3 test cases)\n- TC-6157: Successful Installation\n\n```bash\nnpm install\nnpx playwright install\n```\n\n## Running Tests\n\n### Run all tests\n```bash\nnpm test\n```\n\n### Run tests in headed mode\n```bash\nnpm run test:headed\n```\n\n### Run tests in debug mode\n```bash\nnpm run test:debug\n```\n\n### Run tests in UI mode\n```bash\nnpm run test:ui\n```\n\n### Run tests on specific browser\n```bash\nnpm run test:chromium\nnpm run test:firefox\nnpm run test:webkit\n```\n\n### Run mobile tests\n```bash\nnpm run test:mobile\n```\n\n### Run tablet tests\n```bash\nnpm run test:tablet\n```\n\n### View test report\n```bash\nnpm run report\n```\n\n## Configuration\n\n### Environment Configuration\n\nUpdate `data/config.json` to configure different environments:\n\n```json\n{\n  \"environments\": {\n    \"dev\": {\n      \"baseUrl\": \"https://dev.creditcard.demo\",\n      \"apiUrl\": \"https://api-dev.creditcard.demo\"\n    }\n  }\n}\n```\n\n### Playwright Configuration\n\nUpdate `src/automationScripts/playwright.config.js` to modify:\n- Timeout values\n- Retry logic\n- Reporter settings\n- Browser configurations\n- Viewport sizes\n\n## Page Objects\n\n### LoginPage\n- `navigate()`: Navigate to login page\n- `login(username, password)`: Perform login\n- `enterUsername(username)`: Enter username\n- `enterPassword(password)`: Enter password\n- `clickLogin()`: Click login button\n\n### DashboardPage\n- `navigate()`: Navigate to dashboard\n- `waitForKpiLoad()`: Wait for KPI widgets to load\n- `verifyAllKpiWidgetsVisible()`: Verify all KPIs are visible\n- `getKpiValue(kpiName)`: Get KPI value\n- `getAllKpiWidgets()`: Get all KPI widget elements\n- `getWidgetPositions()`: Get widget positions for layout testing\n\n### CardManagementPage\n- `navigate()`: Navigate to card management page\n- `getAllCards()`: Get all card elements\n- `getCardByNumber(lastFourDigits)`: Get specific card\n- `getCardSpend(lastFourDigits)`: Get card spending amount\n- `getCardUtilization(lastFourDigits)`: Get card utilization percentage\n- `clickSortBySpend()`: Sort cards by spending\n- `getTotalOutstanding()`: Get total outstanding amount\n\n### AnalyticsPage\n- `navigate()`: Navigate to analytics page\n- `getCategoryElement(categoryName)`: Get category element\n- `getAllCategorySpending()`: Get all category spending data\n- `hoverOverCategory(categoryName)`: Hover over category for tooltip\n- `selectDateRange(startDate, endDate)`: Select date range\n- `clickCategoryFilter(categoryName)`: Apply category filter\n- `getMonthLabels()`: Get month labels from chart\n\n## Logging\n\nLogs are generated in the `logs/` directory:\n- `error.log`: Error-level logs only\n- `combined.log`: All logs\n- Console output with color-coded log levels\n\n## Best Practices Implemented\n\n1. **Page Object Model**: All locators in page objects, no locators in test files\n2. **Playwright Native Waits**: Using `expect().toBeVisible()` and built-in auto-waiting\n3. **Data-Driven**: Test data externalized in `data/config.json`\n4. **Logging**: Comprehensive logging using Winston\n5. **Assertions**: Using Playwright `expect` assertions exclusively\n6. **Error Handling**: Try-catch blocks and proper error messages\n7. **Reusability**: Shared methods in page objects (e.g., `login()` used across tests)\n8. **Maintainability**: Clear separation of concerns, organized file structure\n9. **Scalability**: Easy to add new page objects and test cases\n10. **Documentation**: Inline comments and comprehensive README\n\n## Traceability\n\nEach test case is mapped to TestRail test cases:\n- Test Case ID in test name (e.g., TC-6157)\n- Logger statements include test case IDs\n- Test descriptions match TestRail test case descriptions\n\n## Reporting\n\nTest results are generated in multiple formats:\n- **HTML Report**: Interactive HTML report with screenshots and videos\n- **JSON Report**: Machine-readable JSON format\n- **JUnit XML**: For CI/CD integration\n\n## CI/CD Integration\n\nThe framework is CI/CD ready with:\n- Retry logic for flaky tests\n- Parallel execution support\n- Multiple report formats\n- Environment variable support\n- Docker support (Playwright Docker images)\n\n## Maintenance\n\n### Adding New Tests\n1. Create test case in appropriate spec file\n2. Add page methods to relevant page object if needed\n3. Update test data in `data/config.json` if required\n4. Run tests to verify\n\n### Updating Locators\n1. Update locators in page object classes only\n2. Never update locators in test files\n3. Use data-testid attributes where possible\n4. Fallback to CSS/XPath selectors when needed\n\n## Troubleshooting\n\n### Tests failing due to timeouts\n- Increase timeout values in `playwright.config.js`\n- Check network connectivity\n- Verify application is accessible\n\n### Locators not found\n- Verify page objects have correct locators\n- Use Playwright Inspector: `npm run test:debug`\n- Check if elements are in shadow DOM\n\n### Screenshots/Videos not captured\n- Verify `use` configuration in `playwright.config.js`\n- Check `test-results/` directory permissions\n\n## Support\n\nFor issues or questions:\n1. Check logs in `logs/` directory\n2. Review test results in `test-results/`\n3. Run tests in debug mode: `npm run test:debug`\n4. Contact QA team\n\n## License\n\nISC\n
