# Credit Card Dashboard - Playwright Automation Framework\n\n## Overview\nProduction-ready Playwright JavaScript automation framework using Page Object Model for Credit Card Dashboard application.\n\n## Project Structure\n```\nsrc/\n├── automationScripts/\n│   ├── pages/\n│   │   ├── login.page.js\n│   │   ├── dashboard.page.js\n│   │   ├── cardManagement.page.js\n│   │   └── transactionHistory.page.js\n│   ├── utils/\n│   │   ├── logger.js\n│   │   └── config.js\n│   ├── dashboardKPI.spec.js\n│   └── transactionHistory.spec.js\ndata/\n│   └── urls.json\nlogs/\ntest-results/\npackage.json\nplaywright.config.js\nREADME.md\n```\n\n## Test Coverage\n\n### Dashboard KPI Tests (QE-9013)\n- **TC-001**: Verify all dashboard KPIs load within 2 seconds\n- **TC-002**: Verify error indicators for unavailable KPI data sources\n- **TC-003**: Verify KPI performance with large dataset (10 cards, 500 transactions)\n\n### Transaction History Tests (QE-9012)\n- **TC-001**: Verify paginated transaction history with 50 transactions per page\n- **TC-002**: Verify error message for deleted card transaction access\n- **TC-003**: Verify filtered transaction history by date range and category\n\n## Installation\n```bash\nnpm install\n```\n\n## Configuration\nEnvironment URLs are configured in `data/urls.json`. Set the `TEST_ENV` environment variable to switch between environments:\n- `qa` (default)\n- `staging`\n- `production`\n\n## Running Tests\n\n### Run all tests\n```bash\nnpm test\n```\n\n### Run specific test suite\n```bash\nnpm run test:dashboard\nnpm run test:transactions\n```\n\n### Run tests in headed mode\n```bash\nnpm run test:headed\n```\n\n### Debug tests\n```bash\nnpm run test:debug\n```\n\n### Run tests for specific environment\n```bash\nTEST_ENV=staging npm test\n```\n\n## Framework Features\n\n### Page Object Model\n- All locators are encapsulated in Page Object classes\n- Reusable methods for common interactions\n- Shared Page Objects across multiple test cases\n\n### Logging\n- Winston logger with multiple transports (console, file)\n- Separate error and combined logs\n- Configurable log levels\n\n### Configuration Management\n- Environment-specific URLs stored in `data/urls.json`\n- No hardcoded URLs in test or page files\n\n### Assertions\n- Playwright native `expect` assertions only\n- State assertions before element interactions\n\n### Waits\n- Playwright auto-waiting\n- Custom wait utilities in Page Objects\n- No `page.waitForTimeout` unless explicitly necessary\n\n## Test Reports\nTest results are generated in multiple formats:\n- HTML report: `playwright-report/index.html`\n- JUnit XML: `test-results/junit.xml`\n- JSON: `test-results/results.json`\n\n## Logs\nLogs are stored in the `logs/` directory:\n- `error.log`: Error-level logs only\n- `combined.log`: All log levels\n\n## Browser Support\n- Chromium (Desktop)\n- Firefox (Desktop)\n- WebKit (Desktop)\n- Mobile Chrome (Pixel 5)\n- Mobile Safari (iPhone 12)\n\n## Best Practices\n1. All locators reside in Page Object classes\n2. Test files and Page Objects are in `src/automationScripts/`\n3. Page Objects are grouped by feature/page\n4. Methods are reused across test cases\n5. Environment-specific data is in `data/` directory\n6. Comprehensive logging for all actions\n7. Zero syntax errors - production-ready code\n\n## Maintenance\n- Page Objects are feature-based, not test-case-based\n- Shared locators and methods reduce duplication\n- Configuration-driven approach for easy environment switching\n\n## Contact\nFor questions or issues, contact the Senior Automation Framework Engineer team.\n"
